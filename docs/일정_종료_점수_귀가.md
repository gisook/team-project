# 일정 종료·점수·귀가

브랜치: `score-back_to_my_room` (요청 이름의 공백을 Git에서 사용할 수 없어 하이픈으로 정리했습니다.)

설명
1. 응대 종료시 일정 종료 버튼 활성화 되는 기능
2. 일정 종료 버튼 클릭시 파일을 메인서버로 보내고 응답 대기하는 기능
3. 화면에 점수를 출력하는 기능(나중에 응답 결과를 기반으로 점수 출력할때 쓸것이다.)
4. 일정 진행 화면에서 넘어가기 버튼 존재
5. 넘어가기 버튼 클릭시 자취방으로 귀환

## 게임에서의 동작

편의점 화면 오른쪽 위에 **일정 종료**와 **넘어가기**가 있습니다. 손님 세 명의 답변 녹음을 저장하고 응대가 끝나면 일정 종료가 활성화됩니다. 이 시점에는 파일을 자동 전송하거나 귀가하지 않습니다.

일정 종료를 누르면 이번 일정의 미전송 WAV만 기존 메인 서버 `http://121.188.96.177:8000/upload`로 보냅니다. 기존 API에 맞춰 파일 하나씩 multipart/form-data의 `file` 필드로 전송하며, 각 파일의 HTTP 응답을 받은 뒤 다음 파일을 보냅니다. 마지막 응답까지 받으면 결과 화면을 표시합니다. 서버가 응답하지 않는 경우 파일당 12초 후 실패로 처리합니다.

대기 중에는 점수를 `—`로 표시합니다. 모든 전송에 성공하면 **점수: 0점**과 **임시 표시 · 서버 응답 기반 점수 연동 전**을 표시합니다. 임시 0점은 서버가 평가한 점수가 아닙니다. 현재는 점수 표시 화면과 연결 지점만 준비한 상태입니다.

결과 화면에서 **넘어가기**를 누르면 자취방으로 돌아가며 오전은 오후로, 오후는 밤으로 넘어갑니다. 전송 성공만으로 자동 귀가하지 않습니다.

응대 완료 전이나 전송 실패 후에도 넘어가기를 눌러 일정을 건너뛰고 다음 시간대의 자취방으로 돌아갈 수 있습니다. 녹음 중·파일 저장 중·서버 전송/응답 대기 중에는 넘어가기가 잠시 비활성화됩니다. 아직 전송되지 않은 WAV는 귀가해도 남아 있으며, 자취방의 **미전송 녹음 전송**으로 보낼 수 있습니다. 건너뛰기는 미완료 손님을 응대 완료로 기록하지 않습니다.

## 전송 실패와 다시 시작

서버 오류나 시간초과가 발생하면 결과 화면에 전송 재시도가 표시됩니다. 성공 응답을 받은 파일은 제외하고 나머지만 재전송합니다. 이전 일정의 미전송 파일이 있어도 이번 일정의 점수용 전송에는 섞지 않습니다.

현재 일정의 파일별 원본 응답과 점수, 결과 확인 여부는 계정별 일차 저장 파일의 `store_result`에 보관합니다. 게임을 종료했다가 열어도 부분 전송 결과와 남은 파일을 복구하고, 귀가 전의 결과 화면도 다시 표시합니다. 응답을 기다리던 중 게임을 종료했다면 성공 응답이 저장된 파일을 제외한 나머지를 일정 종료로 다시 전송합니다.

## 추후 서버 점수 연결

`scripts/top_down_world.gd`의 `set_schedule_score(value: float)`가 점수 표시·저장 연결 지점입니다. 응답 형식이 확정되면 `_on_upload_finished`의 성공 처리에서 서버 응답을 해석해 이 메서드를 호출하면 됩니다. 원본 응답은 `current_responses`의 `response` 값으로 유지합니다. 현재는 서버 점수 필드나 계산 방식을 임의로 가정하지 않습니다.

## 검증

```text
godot --headless --path . --rendering-method gl_compatibility --script res://tests/top_down_integration.gd
godot --headless --path . --rendering-method gl_compatibility --script res://tests/schedule_submission.gd
godot --headless --path . --rendering-method gl_compatibility --script res://tests/upload_protocol.gd
```

첫 번째는 오전·오후 근무와 수동 제출·귀가·취침을 검사합니다. 두 번째는 일정별 파일 구분, 부분 성공 후 재시도, 결과 복원과 건너뛰기를 검사합니다. 세 번째는 컴퓨터 안의 `127.0.0.1` 테스트 서버를 사용해 실제 HTTPRequest와 WAV 형식, 지연 응답·HTTP 500·시간초과를 검사합니다. 마지막 검사는 로컬 TCP 연결이 허용된 환경이 필요하며 실패 응답을 의도적으로 발생시켜 오류 로그가 출력됩니다. 테스트 파일을 외부 메인 서버로 전송하지 않습니다.
